## 프로젝트

- **자원의 울타리.** DB 커넥션·독립 ERD 초안·용어 사전이 프로젝트에 속하고, 그 아래
  달린 것들(마이그레이션·버전·스냅샷·백업·구조 문서)은 커넥션을 따라 함께 간다
- 서버 컴퓨터·매크로·클러스터·사용자·알림은 프로젝트 **밖**이다. 한 대의 서버가 여러
  프로젝트의 DB를 담고, 매크로 하나가 두 프로젝트를 오갈 수 있다
- 사이드바 맨 위에서 고른다. 바꾸면 보고 있던 화면이 그 자리에서 다시 그려진다
- **참여자만** 그 안을 본다. 참여하지 않은 프로젝트는 있는지조차 보이지 않는다(404).
  슈퍼 어드민만 예외로 전부 본다
- 참여는 DB별 등급보다 **앞선 관문**이다. 참여하지 않으면 등급이 무엇으로 적혀 있든
  목록에 나오지 않고, 참여했다고 다 열리는 것도 아니다(그 안에서 등급을 따로 정한다)
- 참여자는 프로젝트 화면과 사용자 → 권한 설정 두 곳에서 정할 수 있고 같은 값이다
- 만들기·이름 바꾸기·지우기는 커넥션 관리자(어드민 이상). 만든 사람은 자동 참여자
- **빈 프로젝트만 지운다.** 안에 든 것이 있으면 몇 개인지 알려 주고 멈춘다
- 커넥션 이름은 **프로젝트 안에서만** 유일하면 된다
- 이미 쓰던 앱을 올리면 기본 프로젝트가 하나 생기고 있던 자원과 사용자가 모두 그 안에
  들어간다. 새로 설치한 앱에는 프로젝트가 없다

## 인증 · 사용자 · 권한

- 슈퍼 어드민 부트스트랩 (사용자가 없을 때 랜덤 비밀번호 생성 → 터미널 출력)
- 세션 로그인/로그아웃, 첫 로그인 시 비밀번호 변경 강제
- **2단계 인증(TOTP)** — 각 사용자가 자율적으로 켜고, 슈퍼 어드민이 전체 의무화할 수 있다.
  자세한 내용은 [2단계 인증](getting-started.md#2단계-인증-totp) 참고
- 사용자 CRUD, 역할(슈퍼 어드민 / 어드민 / 멤버), 비밀번호 재설정
- 로그인할 때 접속 IP를 기록하고, 사용자 목록에서 **마지막 로그인 시각과 그때의 IP**를 함께 표시
  (프록시 뒤에서는 `-trust-proxy`로 실제 클라이언트 IP를 기록한다)
- 내 프로필 화면: 표시 이름·이메일 수정, **미리 그려둔 라인 아이콘 16개 중에서 프로필 아이콘 선택**
  (직무 8개: DBA·개발자·분석가·운영/SRE·아키텍트·보안·지원·기획 / 사람 8개: 기본·안경·수염·모자·긴 머리·곱슬머리·묶은 머리·웃는 얼굴),
  또는 **이미지 직접 업로드 / 주소(URI)에서 가져오기** (PNG·JPEG·GIF·WebP, 기본 512KB 상한)
- **프로젝트 참여**가 첫 관문이고(위 참고), 그 안에서 사용자별 접근 범위
  (모든 DB / 선택한 DB만 / 특정 DB 제외) × 능력 등급(모니터링 < ERD < 마이그레이션)
- 그와 **독립적인 데이터 능력**(데이터 조회 / 데이터 수정 / SQL 실행)을 부여
- 권한은 **서버 단위로 일괄 부여하고 DB 단위로 예외를 둔다**. 좁은 쪽이 이긴다 —
  "이 서버 전체에 모니터링, 단 billing DB만 접근 불가"가 한 화면에서 표현된다
- 전역 권한(매크로 사용 / 셸 스크립트 실행 / 외부 API 호출)
- 감사 로그 (인증, 사용자, 커넥션, 권한, 스키마 조작, 데이터 조회·수정·SQL 실행, 매크로 실행 및 권한 거부 이력)

## 데이터 조회 · 수정 · SQL 실행

- 테이블 브라우저: 페이지 단위 조회, 컬럼별 조건(=, ≠, 포함, 시작, 대소, NULL 여부), 전체 컬럼 검색,
  컬럼 정렬, 행 추가·수정·삭제 (수정은 **기본키로만** 지정한다)
- **외래키 따라가기**: 행 상세에서 FK 컬럼을 누르면 대상 행이 **오른쪽에 펼쳐지고**,
  거기서 또 따라가면 그 오른쪽으로 이어진다. `user_id = 481`이 누구인지 보려고 표를
  옮겨 다니지 않아도 된다
- MongoDB는 컬렉션 문서 조회·편집(표 + 원본 JSON 양쪽), Redis는 키 접두사 그룹과 값·TTL 조회·편집
- SQL 콘솔: 여러 문장 실행, 읽기 전용 스위치(기본 켜짐), 결과 표, 실행 이력(브라우저에만 저장).
  MongoDB는 `runCommand` JSON, Redis는 명령 한 줄씩
- 편집기에 **줄 번호**가 붙는다. DB가 "3행에서 오류"라고 알려줄 때 그 자리를 바로 찾기 위해서다
- **구문 검사**: 실행하지 않고 문장을 확인한다. 대상 DB의 드라이버로 문장을 *준비만* 해 보므로
  문법뿐 아니라 **테이블·컬럼 이름의 오타까지** 잡히고, 아무것도 실행되지 않는다.
  준비만으로 확인할 수 없는 문장(`USE`, 트랜잭션 제어)은 "오류"가 아니라 "확인 불가"로 구분해 표시한다
- **포맷팅**: 들여쓰기와 예약어 대소문자를 다듬는다. 브라우저에서 처리하며 문자열·주석은 원문 그대로 둔다
- **실행 분석**: 대상 DB의 방식으로 실행 계획을 본다(PostgreSQL `EXPLAIN (ANALYZE, BUFFERS)`,
  MySQL `EXPLAIN ANALYZE`, SQLite `EXPLAIN QUERY PLAN`). ANALYZE는 문장을 실제로 실행하므로
  읽기 전용으로만 돌고, 쓰기 문장은 거부된다 — `EXPLAIN ANALYZE DELETE …`는 행을 지운다

## 백업 · 복구

- **논리 덤프**: 구조(DDL) + 데이터(INSERT)를 담은 텍스트 파일을 만든다. 범위(전체/구조만/데이터만),
  대상 테이블 선택, DROP 문 포함 여부를 고를 수 있고 gzip으로 저장된다
- MongoDB는 줄 단위 확장 JSON, Redis는 줄 단위 명령으로 덤프한다
- **복구**: 저장된 백업을 원래 커넥션 또는 같은 종류의 다른 커넥션에 되돌린다
  (운영 데이터를 개발 DB로 옮겨 재현하는 것이 가장 흔한 용도다)
- 내려받기·내용 미리보기·삭제, 보존 기간이 지난 백업 자동 정리
- 매크로의 "백업 만들기" 노드로 마이그레이션 앞에 백업을 자동으로 남길 수 있다

## 스키마 버전 롤백

- 버전 이력에서 특정 버전을 골라 되돌린다. 현재 구조와의 차이를 보여준 뒤
  **마이그레이션 계획**을 만들고, 기존 흐름(검토 → 승인 → 사전 검사 → 실행)을 그대로 탄다
- 적용이 끝나면 새 버전이 **"롤백" 유형**으로 이력에 등록된다

## 구문 강조

- SQL 콘솔, 매크로의 코드 칸(SQL·Lua·JSON·셸), 마이그레이션 SQL 미리보기, 백업 내용 보기에
  구문 강조가 적용된다. 외부 라이브러리 없이 토크나이저와 규칙 표로 직접 구현했다

## 매크로 (노드 에디터 + GopherLua)

- 노드를 이어 붙여 DB 자동화를 만든다. 내장 노드 19종: 흐름(로그·변수·분기·반복·대기·중단),
  DB(SQL 조회/실행·데이터 조회/수정), DB Studio 조작(스키마 읽기·버전 확정·드리프트 확인·연결 확인·
  백업 만들기·매크로 호출), 스크립트(bash/powershell·Lua)
- **사용자 노드**를 Lua로 작성해 등록할 수 있다. 전역(모든 매크로) 또는 해당 매크로 전용, 버전 관리됨
- 모든 매크로는 **실행 전에 저장**되고 버전이 쌓인다. 롤백은 옛 그래프로 새 버전을 만든다
- 실행 로그는 노드 단위로 남고 SSE로 실시간 스트리밍된다. 결과는 **성공 / 실패 / 취소**로 분류된다
- **매크로는 만든 사람의 것이다.** 기본은 비공개이고, 공유는 셋 중 하나로 넓어진다:
  공개 전환(조회+실행 / 수정 허용 중 선택), 협업자 지정(수정·실행·관리 가능, 삭제는 불가),
  슈퍼어드민(모든 매크로 조회·수정·관리·삭제). 전역 사용자 노드도 같은 규칙을 따르고,
  매크로 전용 노드는 소속 매크로의 권한을 물려받는다
- 접근 권한과는 별개로 **실행 권한은 사람마다 다르며**, 부족하면 화면이 이유를 적고
  실행 버튼을 비활성화한다
- **외부 API 호출**: Lua에서 `http.get/post/request`를 쓰거나 `HTTP 호출` 노드를 놓는다.
  응답이 JSON이면 파싱해서 함께 준다. 별도 권한(`http.call`)이 필요하고, 호출한 주소·상태·소요
  시간이 실행 로그에 남는다. 링크로컬(클라우드 메타데이터) 주소는 항상 막힌다

## 매크로 자동 실행 (정기 · 조건)

- **정기 실행**: 5필드 cron(`분 시 일 월 요일`)과 IANA 시간대. 흔한 주기는 목록에서 고르고,
  저장 전에 **다음 실행 시각 5개를 미리 본다**
- **조건 실행**: 모니터링 이벤트(임계치 위반·접속 실패·스키마 외부 변경·수집 실패)가 **새로 열릴 때**
  실행한다. 종류·심각도·지표·커넥션으로 좁히고, 최소 간격으로 연속 발화를 막는다
- 트리거는 **만든 사람(소유자)의 권한으로** 실행된다. 서비스 계정을 두지 않는 이유는 아래 설계 노트 참고.
  소유자의 권한이 회수되거나 계정이 비활성화되면 그 트리거는 실패하고 **스스로 꺼진다**
- 이벤트로 시작한 실행에는 `trigger` 변수로 어떤 이벤트였는지가 들어온다
- 이전 실행이 끝나지 않았으면 건너뛴다(기본값). 앱이 꺼져 있던 동안 지난 실행은 따라잡지 않는다

## DB 서버와 커넥션

- **서버 하나에 DB 여러 개.** 접속 정보와 자격증명은 서버가 갖고, 관리 대상 DB가 그 아래에 달린다.
  비밀번호를 한 번 고치면 그 서버의 모든 DB에 반영된다
- 서버를 등록하면 **실제로 접속해 DB 목록을 읽어와** 체크박스로 여러 개를 한 번에 추가한다
  (PostgreSQL·MySQL·MS-SQL·MongoDB·Redis). 시스템 DB와 이미 등록된 DB는 표시만 하고 기본 선택에서 뺀다.
  Oracle(서비스명)과 SQLite(파일 경로)는 대상이 곧 접속 정보라 직접 입력한다
- 같은 서버를 여러 번 등록했다면 **서버 병합**으로 합친다. 겹치는 DB가 있으면 전부 알려주고 아무것도 옮기지 않는다
- 등록/수정/삭제 + 실제 연결 테스트 (MySQL, PostgreSQL, MS-SQL, Oracle, SQLite, MongoDB, Redis)
- DB 종류별 접속 옵션(SSL/TLS, 인증 DB, 레플리카셋 등). MongoDB는 **인증 방식(authMechanism)**을
  목록에서 고르고 방식별 속성(`authMechanismProperties`)을 함께 지정할 수 있다.
  Oracle은 **스키마 소유자(`owner`)**를 지정할 수 있다 — 비우면 접속 계정의 스키마를 보고,
  관리 계정으로 붙어 앱 계정의 테이블을 볼 때 지정한다(구조 화면과 데이터 화면에 함께 적용된다)
- 자격증명 AES-256-GCM 암호화 저장

## 스키마

- 라이브 introspect: 테이블·컬럼·PK·인덱스·FK·체크제약·뷰·enum·주석·통계
- MongoDB는 문서 샘플링으로 필드 구조 추론(필드별 존재 비율 포함), Redis는 키 접두사 그룹 요약
- DB별 타입을 논리 타입으로 정규화 (MySQL `int(11)` = PostgreSQL `integer` = Oracle `NUMBER(10,0)`)
- 두 커넥션 스키마 비교 → 변경 목록(파괴적 변경 표시) + up/down SQL 생성
- 전체 스키마의 CREATE 스크립트 생성, 다른 DB 종류로 타입 변환 출력
- 구조 지문(fingerprint) — 외부 편집 감지의 기반

## 모니터링

- 커넥션별 주기 폴링 → 표준화된 지표 수집 (DB 종류가 달라도 같은 의미면 같은 이름)

- 이벤트 개시/해소/확인, 같은 원인은 발생 횟수로 누적
- 원본 48시간 + 시간 단위 롤업 90일, 범위에 따라 자동 선택

## 서버 컴퓨터 감시 (호스트)

- DB Studio가 도는 컴퓨터 자신의 CPU·메모리·스왑·디스크·네트워크를 같은 주기로 수집
  (외부 라이브러리 없이 리눅스는 `/proc`, 윈도우는 `kernel32`/`iphlpapi`를 직접 읽는다)
- 임계값(경고/심각)과 지속 시간을 화면에서 고친다. 디스크는 지속 시간을 따지지 않는다
- 호스트 재부팅, 앱 시작, **비정상 종료**(강제 종료·전원 차단·크래시),

- 커넥션에 속하지 않는 이벤트이므로 **커넥션 관리 권한**이 있는 계정에게만 보인다
- 읽지 못한 지표는 0으로 채우지 않고 이유를 화면에 남긴다

## 알림 (Mattermost · Slack · Discord)

- 이벤트가 생기면 메신저 채널로 보낸다. 들어오는 웹훅(incoming webhook) 하나면 되고,
  봇 토큰·API 권한 관리가 필요 없다
- 세 메신저를 한 설정으로 다룬다. Mattermost와 Slack은 본문 구조가 같고(Mattermost가
  Slack 호환) 다른 것은 **글자 문법**뿐이다 — Slack의 mrkdwn은 굵게가 별표 하나,
  링크가 `<주소|글자>`다. 그 차이는 함수 두 개(bold·link)에 가둬 두었다
- **Discord는 본문 구조가 다르다**: attachments 대신 embeds 이고 색이 문자열이 아니라
  정수다. 그 차이는 `discordWire` 한 곳에 가둬 두었다. 채널은 웹후크를 만들 때 정해져
  본문으로 바꿀 수 없고(보내는 이름은 반영된다), 본문 상한 2000자를 넘으면 잘라 보낸다 —
  잘린 알림과 오지 않는 알림은 다른 이야기다
- Slack 앱 웹훅은 채널·보내는 이름 지정을 무시한다(웹훅을 만들 때 고른 채널로 간다).
  화면이 고른 메신저에 맞춰 그 사실을 미리 알려준다
- 웹훅 주소는 **암호화해 저장**하고 화면·감사 로그에는 마스킹해 남긴다
  (그 주소 하나가 곧 그 채널에 글을 쓸 권한이다)
- 무엇을 보낼지 고른다: 최소 심각도, 이벤트 종류, 해소 알림 포함 여부
- 심각도를 **색**으로 먼저 알린다(심각/경고/정보/해소). 값·기준·지속 시간을 함께 싣고,
  앱 주소를 넣어 두면 이벤트 화면 링크를 붙인다
- 전송은 큐를 거쳐 비동기로 나간다(폴러를 막지 않는다). 실패하면 세 번까지 재시도하고,
  마지막 결과는 설정 화면의 **전송 상태**에 남는다
- 링크로컬 주소(클라우드 메타데이터)로는 보내지 않는다. 사설망은 막지 않는다 —
  Mattermost는 사내에 두는 경우가 훨씬 많다

## 로그 탐색 · 쿼리 분석

- 시간순 로그(슬로우 쿼리, 서버 오류, 실행 중 쿼리)와 누적 쿼리 통계를 각각의 탭으로 분리
- MySQL `slow_log`/`performance_schema`, PostgreSQL `pg_stat_statements`/서버 로그,
  MS-SQL `dm_exec_query_stats`/`sp_readerrorlog`, Oracle `v$sql`/알럿 로그,
  MongoDB 프로파일러, Redis `SLOWLOG`
- 소스별 가용성과 활성화 방법을 화면에서 안내 (로그 소스는 DB 설정에 의존한다)
- SQL 정규화 + 다이제스트로 리터럴만 다른 쿼리를 하나로 묶어 Top-N 집계
- 필터: 기간, 소스, 심각도, 최소 소요 시간, 부분 문자열/정규식 검색, 정렬 기준 4종

## 구조 (연결된 DB를 ERD로 보기)

- ERD 설계와 같은 캔버스로 **지금 연결된 DB의 구조**를 본다. 목적이 반대다 —
  저쪽은 만들고 싶은 것을 그리고, 이쪽은 있는 것을 읽는다
- **스키마는 편집할 수 없다.** 바꿀 수 있는 것은 읽는 사람의 정리뿐이다:
  카드 위치, 캔버스 메모, 그룹 묶기
- 그 정리는 **계정별로 저장된다**. 결제를 보는 사람과 배송을 보는 사람은 같은 스키마를 다르게
  늘어놓아야 하고, 한 사람의 정리가 다른 사람의 것을 덮어쓰면 둘 다 못 쓴다
- 최신 상태와 **저장된 스키마 버전** 중에서 시점을 고를 수 있다 ("언제부터 이랬지"에 답하려고
  다른 화면으로 나가지 않는다)
- 스키마에 새 테이블이 생기면 기존 카드와 겹치지 않는 자리에 자동으로 놓는다
- "이 구조로 초안 만들기"로 곧바로 ERD 설계에 넘어간다

## ERD 설계 (동시 편집)

- SVG 캔버스: 테이블 카드 드래그, 확대/축소·이동, 관계선, 캔버스 메모, 카드 접기
- 편집: 테이블·컬럼·기본키·인덱스·외래키·체크제약·enum (사이드 패널에서 직접)
- **컬럼 타입 고르개**: 대상 DB가 지원하는 모든 타입을 목록에서 고르고, 타입이 요구하는 것만 물어본다
  (길이·자릿수·값 목록·초 정밀도, MySQL의 UNSIGNED, PostgreSQL의 배열). 목록에 없는 타입은
  **직접 입력**으로 그대로 쓸 수 있다. 목록의 출처는 서버(`internal/schema/catalog.go`)다
- **자동 증가(AUTO)**는 타입 창 안에서 켜고 끈다 — 붙일 수 있는 타입을 골랐을 때만 그 칸이
  보인다. 어디까지 되는지는 서버 카탈로그가 타입별로 표시하고(DB마다 다르다: MS-SQL은
  소수 자릿수 0인 DECIMAL에도, SQLite는 INTEGER에만), 정수가 아닌 타입으로 바꾸면 함께 꺼진다.
  생성되는 DDL도 DB마다 다르다(AUTO_INCREMENT / IDENTITY / GENERATED AS IDENTITY /
  INTEGER PRIMARY KEY)
- **도메인(타입 재사용)**: "email = VARCHAR(320)"처럼 이름을 붙여 두고 컬럼에서 골라 쓴다.
  정의를 고치면 그 도메인을 쓰는 컬럼이 함께 바뀌고, 컬럼에서 타입을 직접 고치면 그 컬럼은
  도메인에서 벗어난다. 상단 **도메인** 탭에서 모아 관리한다
- 대상 DB의 현재 스키마를 가져와 초안 시작 (그 시점 스냅샷을 기준으로 기록)
- **대상 DB 없이도** 새 설계도를 그릴 수 있다. DB 문법만 고르면 되고, 결과는 SQL로 내보낸다 —
  설계는 DB를 만들기 전에 시작되는 일이 더 많다.
  이런 초안은 로그인한 사람이면 누구나 함께 편집하고, 삭제·설정 변경은 만든 사람과 어드민만 한다
- **SQL 불러오기**: DDL 스크립트(파일 또는 붙여넣기)를 읽어 초안에 얹는다.
  이름이 같은 테이블은 덮어쓰고(좌표와 색은 유지), `DROP TABLE`은 초안에서도 지우며,
  초안에만 있는 테이블은 그대로 남는다. 적용 전에 **무엇이 바뀌는지 미리 보여준다**
- **SQL 내보내기**: 초안 전체를 만드는 CREATE 스크립트를 복사하거나 파일로 받는다.
  대상 DB 종류를 바꿔 내보낼 수도 있다(타입 변환 경고를 함께 표시)
- 마이그레이션을 만들면 **실행될 SQL을 그 자리에서 보여주고 복사**할 수 있다
- 여러 사용자 동시 편집: 서버 권위 op-log + 필드 단위 LWW, 순번(seq) 기반 정합
- **되돌리기 / 다시실행** (Ctrl+Z, Ctrl+Shift+Z): **내가 한 편집만** 한 칸씩 물러난다.
  남이 그 사이에 같은 대상을 고쳤다면 덮어쓰지 않고 이유를 말하며 멈춘다.
  사람·문서마다 30단계이고, 새로고침해도 30분 동안 남는다.
  AI가 만든 편집도 같은 방법으로 되돌린다 (SQL 불러오기는 제외)
- 프레즌스: 참여자 목록, 커서 위치, 선택 중인 테이블 표시.
  참여자 아이콘을 누르면 **그 사람의 화면을 따라간다** (캔버스를 직접 끌면 풀린다)
- 문서별 채팅 (영속) — 설계 의도를 남겨 리뷰에 쓴다.
  대화 탭을 보고 있지 않으면 새 메시지가 캔버스 위에 카드로 뜬다
- **문서 안의 AI 대화**: 초안을 고치는 툴 8개(테이블·컬럼·기본키·외래키·인덱스 추가/수정)만
  가진 대화를 문서마다 연다. AI가 만든 변경은 초안에 즉시 반영되고 같은 문서를 연 모두에게
  보인다(실제 DB는 바뀌지 않는다). 지우는 툴은 없다 — 되돌리기가 없기 때문이다.
  이 대화는 나만 보며, 쓸 만한 답만 골라 **전체 대화로 공유**한다
- 연결이 끊기면 자동 재연결하고, 확인받지 못한 편집을 다시 전송 (중복 적용 방지)
- 초안 ↔ 대상 DB diff와 적용 SQL 미리보기, 편집 이력 조회

## 스키마 버전 · 마이그레이션

- 버전 이력: 최초 등록 / 마이그레이션 / 외부 편집 / 롤백을 출처별로 구분해 기록
- 버전 하나를 **비교 없이 단독으로** 볼 수 있다: `구조 보기`(그 시점 구조를 ERD로),
  `SQL 보기`(CREATE 스크립트 — 복사·파일 저장). 옛 구조를 재현 환경에 다시 만들거나
  사고를 조사할 때 필요한 것은 차이 목록이 아니라 완전한 스크립트다
- 앱 밖에서 바뀐 스키마를 드리프트 이벤트에서 한 번에 "외부 편집" 버전으로 확정
- ERD 초안 → 마이그레이션 계획(up/down SQL, 파괴적 변경 표시, 경고)
- 리뷰 요청 → 승인/반려 → 승인됨 상태만 실행 가능 (상태 전이 규칙을 한 곳에서 강제)
- 실행 전 사전 검사: 계획을 만든 시점의 구조 지문과 현재 DB를 비교해 불일치 시 차단
- 운영 DB: 승인 2명(본인 승인 불가), 커넥션 이름 확인 문구, 백업 훅(`-backup-cmd`)
- 문장 단위 실행 기록 — MySQL·Oracle은 DDL이 트랜잭션으로 되돌아가지 않으므로
  "어디까지 적용됐는가"가 복구의 출발점이다
- 롤백: 저장된 down SQL 실행 + 결과를 새 버전으로 등록

## Git 연동 (GitHub · GitLab · Bitbucket)

- 저장소와 토큰 등록 (self-hosted 인스턴스 지원, 토큰은 암호화 저장·응답에 미노출)
- 연결 확인: 저장소 접근과 쓰기 권한을 미리 검사하고 부족하면 알려준다
- 마이그레이션 → 브랜치 생성 → up/down SQL과 목표 스키마(JSON)를 **한 커밋**으로 → PR/MR 생성
- PR 설명에 변경 목록·파괴적 변경 사유·되돌릴 수 없는 항목·앱 내 검토 의견을 담는다
- 브랜치/경로 템플릿 (`{date}` `{ts}` `{slug}` `{conn}` `{env}` `{version}` `{id}`)
- 같은 브랜치의 열린 PR이 있으면 재사용, 브랜치가 있으면 그 위에 커밋
- 푸시 이력: 성공·실패를 실패 단계와 함께 기록

- **허용 모델 목록**: 키를 넣고 모델 목록을 불러와 쓸 수 있는 모델을 고른다.
  비워 두면 제한 없음, 채우면 그 안에서만 고를 수 있다(기본 모델도 그중 하나여야 한다)
- 사용자는 **대화마다 모델을 고르고 도중에 바꾼다** — 조사는 싼 모델로 시작하고
  판단이 필요한 대목에서 좋은 모델로 옮길 수 있다
- **메뉴에서 누르면 떠 있는 팝업으로 뜬다** — 보고 있던 화면(스키마·데이터·ERD)이
  그대로 남는다. 옮기고 크기를 바꿀 수 있고 그 배치를 기억하며, 좁히면 대화 목록이
  위로 눕는다. 팝업 머리의 버튼으로 전체 화면(`/assistant`)으로 옮겨 간다 —
  긴 조사에는 넓은 화면이 낫고, 주소로 공유할 수도 있어야 한다
- 대화 세션(소유자만 열람) + SSE 스트리밍 채팅, 토큰 사용량 집계
- 답변은 **마크다운으로 렌더링한다**(제목·목록·표·코드 블록·링크). 직접 만든 렌더러이며
  innerHTML을 쓰지 않는다 — 모델이 만든 문자열에는 조회한 DB 값이 섞여 있다
- 대화 머리에서 **이름·모델·대상 DB를 바로 바꾼다.** 대상 DB는 시스템 프롬프트에 실려
  나가므로 모델이 "어느 DB를 볼까요?"라고 되묻지 않는다
- 조회 툴 22종: 커넥션·상태·지표·이벤트·로그·스키마·스키마 비교·ERD·마이그레이션·버전,
  데이터 조회·목록·SQL 조회, 백업 목록, 매크로 목록·실행 기록,
  **서버 목록, 서버의 원격 DB 목록, 자동 실행 트리거 목록**
- 변경 툴 16종(ERD 초안 생성, 마이그레이션 생성·리뷰 요청·실행, 버전 확정, Git 푸시,
  데이터 수정, SQL 실행, 백업 생성·복구, 매크로 실행, 버전 롤백,
  **DB 일괄 등록, 자동 실행 트리거 생성·켜기끄기·삭제**):
  **AI는 실행하지 않고 제안만 만들고**, 사용자가 승인해야 실행된다
- **자격증명을 인자로 받는 툴은 없다.** 서버 등록·비밀번호 변경을 툴로 만들지 않은 이유가 이것이다 —
  인자로 받으면 비밀번호가 대화 기록에 남고 AI 프로바이더로 전송된다. 서버 삭제·병합도
  되돌릴 수 없는 폭이 커서 화면에만 둔다
- 툴은 대화 중인 사용자의 권한으로 실행된다 — 권한이 없는 DB는 어시스턴트도 볼 수 없다
- 승인 후에도 기존 안전장치(검토자 승인 수, 사전 검사, 운영 DB 확인 문구)가 그대로 적용된다
- **ERD 화면 안의 대화는 이 목록을 쓰지 않는다.** 초안에 매인 대화에는 문서를 고치는 툴만
  넘어가며([ERD 설계](#erd-설계-동시-편집)), 그쪽은 실제 DB에 닿지 않으므로 승인 단계도 없다

## MCP 서버 (외부 AI 클라이언트 연동)

- Claude Code·Claude Desktop 같은 MCP 클라이언트가 `POST /mcp`로 붙어 위 툴 38종을 그대로 쓴다
  (앱 안의 어시스턴트와 **같은 툴 레지스트리**를 공유한다)
- 전송은 Streamable HTTP + JSON-RPC 2.0. 프로토콜 판 `2025-06-18`·`2025-03-26`·`2024-11-05` 협상
- 인증은 **API 토큰**(`Authorization: Bearer …`). 토큰은 발급한 사용자의 권한을 그대로 쓴다
- 토큰 범위는 읽기/쓰기 둘 중 하나다. 읽기 토큰에는 변경 툴이 **목록에도 보이지 않는다**
- 토큰은 프로필 화면에서 발급·재발급·삭제하며, 원문은 발급 순간 한 번만 표시된다(해시만 저장)
- **재발급은 값만 바꾼다**(이름·범위·만료는 그대로). 값이 샜을 때 할 일은 대개 토큰을 버리는
  것이 아니라 값을 바꾸는 것이다 — 클라이언트 설정이 가리키는 것은 이름이고, 새로 만들어
  옮기면 고칠 곳이 늘어나며 그 사이 옛 토큰 지우는 것을 잊는다. 옛 값은 그 즉시 401이다

## REST API (스크립트·CI·외부 서비스 연동)

- MCP 클라이언트가 아닌 것들을 위한 두 번째 문. 같은 토큰, 같은 툴 38종, 같은 권한 판정을
  JSON-RPC 봉투 없이 `curl` 한 줄로 쓴다
- `GET /api/tools` 목록(인자 스키마 포함) · `GET /api/tools/{name}` 스키마 하나 ·
  `POST /api/tools/{name}` 실행(본문이 곧 인자) · `GET /api/me` 토큰 주인과 범위
- 결과는 파싱된 JSON으로 온다. 오류는 상태 코드로 갈린다 —
  401 자격증명 · 403 권한/범위 · 404 없는 툴 · 400 잘못된 본문 · 422 툴이 거절
- 모든 호출이 감사 로그에 남는다(`api.tool.call`, `api.tool.denied`, `api.auth.denied`)

## MongoDB · Redis 전용 탐색

- MongoDB: 컬렉션별 문서 수·저장 크기·평균 문서 크기, 인덱스 크기와 속성(unique/sparse/TTL/partial),
  **서버 재시작 이후 사용 횟수**(쓰이지 않는 인덱스는 삭제 후보로 별도 표시), 뷰/시계열 구분,
  필드별 존재 비율과 혼합 타입 표시
- Redis: 메모리 사용량·상한·정책·단편화, 지속성 상태(AOF/RDB·마지막 저장), 적중률·축출·만료,
  DB별 키 수와 TTL 설정 비율, 키 접두사 그룹(ID 세그먼트를 `*`로 묶음)의 타입 분포와 TTL 비율,
  메모리를 많이 쓰는 큰 키, 명령별 호출·평균 소요 시간
- 구조와 통계만 보여주며 **문서 내용이나 키 값은 반환하지 않는다** (데이터 접근은 권한 모델에 없다)
- 어시스턴트도 같은 정보를 `explore_nosql` 툴로 조회한다 (권한은 동일하게 적용)

## 메뉴얼 (`/manual`)

- 앱 안에 들어 있는 사용 설명서. 사이드바에서 **새 탭으로** 연다 —
  읽으려고 하던 일을 접어야 하면 결국 읽지 않는다
- 화면별 사용법, 권한 모델, 매크로와 **Lua 레퍼런스**(샌드박스 범위, `db`·`http`·`sh`·
  `json`·`log`·`macro` API, 반환값과 포트)
- 매크로 노드 목록은 **서버에서 받아 그린다** — 손으로 적은 목록은 노드가 늘어난 다음에
  틀린 목록이 된다

## 분산 스토리지 (하둡 · Ceph)

- HDFS와 Ceph를 커넥션으로 등록해 용량·상태·구성원을 본다. 권한은 DB와 같다 —
  조회는 모니터링 등급, 변경은 데이터 수정 능력
- 하둡: 데이터노드 수, 손실·복제 부족 블록, 세이프모드, HDFS 경로 탐색,
  YARN 애플리케이션과 자원 사용률
- Ceph: OSD 상태, 풀, PG 이상, 오브젝트 버킷(RGW)
- 하둡에서는 디렉터리 생성·이름 변경·삭제를 할 수 있다. 재귀 삭제는 **파일 수·디렉터리
  수·용량을 먼저 세어** 보여주고 이름을 다시 입력하게 한다. 루트(/)는 지울 수 없다
- **Ceph는 조회 전용이다** — 풀 삭제나 OSD 조작은 되돌릴 수 없다
- 등록만 하면 기본 룰이 걸린다: 용량 85%(주의)·95%(위험), 노드 이탈, 상태 위험,
  HDFS 손실 블록

## 메시지 브로커 (RabbitMQ · Kafka)

- 첫 질문이 "쌓이고 있나"이므로, 개요는 **밀린 메시지**와 그것을 줄이는 쪽
  (소비자·컨슈머 그룹)을 나란히 놓는다
- RabbitMQ: 큐(대기·미확인·소비자·초당 발행/소비), 익스체인지, 클라이언트 연결,
  노드 상태와 메모리·디스크 알람. 큐 비우기·삭제, 연결 끊기 가능
- Kafka: 토픽(파티션·복제·리더 없는 파티션), 토픽 설정, 컨슈머 그룹과 랙.
  카프카 프로토콜로 직접 붙으므로 REST 프록시가 필요 없다. **조회 전용이다**
- **메시지는 쌓여 있는데 소비자가 없는** 큐·그룹을 목록에서 따로 표시한다

## 클러스터 (여러 서버)

- 여러 서버에서 띄운 DB Studio를 하나처럼 다룬다. 한 대가 마스터, 나머지가 리플리카다
- 어느 노드에 접속해도 같은 계정·같은 DB 목록·같은 이력을 본다. 조회는 접속한 노드가
  바로 답하고, 변경은 마스터가 처리한 뒤 그 결과가 돌아온다
- 복제는 **행 단위**다(트리거로 변경을 기록 → 리플리카가 순서대로 적용). 첫 동기화와
  따라잡을 수 없는 경우는 스냅샷으로 통째로 맞춘다
- 마스터가 멈추면 리플리카는 **읽기 전용**으로 계속 동작한다. 자동 승격은 하지 않는다 —
  진실이 둘이 되는 것보다 잠깐의 정지가 낫다
- 사설망 안에 있어 특정 서버에서만 닿는 DB에는 **담당 노드**를 지정한다
- 클러스터 화면에서 노드 목록, 복제 지연, 각 서버 컴퓨터의 CPU·메모리·디스크를 함께 본다
- 장애 대응(승격 절차, 증상별 조치)은 앱 안 설명서의 "클러스터" 항목에 정리되어 있다
